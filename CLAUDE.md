# Working in this repo

Personal site plus the Study Hub (`study/`). Most sessions here build or fix study materials.

**Before building or changing a study material, read `study/src/docs/README.md`**, then the
files it points to: `STATUS.md` (what is live and pending), `PLAYBOOK.md` (the full process,
template anatomy, verification and publishing), `design/DESIGN-PROMPTS.md` (how to write the
Claude Design prompt the user runs first), and the note for the class in `classes/`. Course
documents and attachments are in `study/src/sources/`. That whole folder is gitignored and
exists only on this Mac; if it is missing, `node study/tools/publish.mjs --pull` recovers the
material sources but not the notes.

Rules that always apply:

- Never commit `study/src/`. Commit `.enc` files, `study/materials.json` and shell files only.
- Never run anything that calls a paid API; materials are written by hand in-session.
- Do not open the retired "Adaptive Study System" project on the Desktop or anything in it.
- Content only from the named course documents, never general knowledge.
- No em dashes or en dashes anywhere, including commit messages.
- Commit only as `ayatdzcollection-sketch <283192794+ayatdzcollection-sketch@users.noreply.github.com>`.
  Never a personal name or email, in commits, files or the repo description. A local
  pre-commit hook enforces it; do not bypass it with --no-verify.
- Publishing needs the admin code from the codes file; if it is missing or rejected, ask the
  user. Ten wrong tries locks the address.
- Derived materials (`fraser-review`, `acct/topic1`) are generated by scripts in
  `study/src/tools/`; change the generator or the template, never the output.
- Hub contract, storage, sync and offline behaviour: `study/README.md`.
